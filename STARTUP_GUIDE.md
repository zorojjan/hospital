# Медми Клиника - Руководство по запуску

## Структура проекта

Это Django приложение больницы с поддержкой:
- **Пациентов**: Самостоятельная регистрация по телефону
- **Врачей**: Создание только администратором
- **Записей на приём**: Управление врачом и пациентом
- **Новостей**: Публикация администратором на главной странице

## Быстрый старт

### 1. Подготовка окружения

```powershell
# Перейти в папку проекта
cd c:\hospital_project

# Активировать виртуальное окружение (если используется)
# .\venv\Scripts\Activate.ps1
```

### 2. Создание и применение миграций

```powershell
# Создание начальной БД
python manage.py makemigrations

# Применение миграций
python manage.py migrate
```

### 3. Создание администратора

```powershell
python manage.py createsuperuser
```

Задайте:
- **Username**: admin (или ваше имя)
- **Email**: admin@example.com (можно оставить пустым)
- **Password**: Придумайте сложный пароль

### 4. Заполнение данными (опционально)

```powershell
# Создание врачей
python manage.py populate_doctors.py

# Создание локаций
python manage.py populate_locations.py

# Создание отзывов (после создания врачей)
python manage.py populate_reviews.py
```

После этого создайте учётные записи врачей в админке:
```powershell
python manage.py create_doctor_accounts.py
```

### 5. Запуск сервера

```powershell
python manage.py runserver
```

Сервер запустится на `http://127.0.0.1:8000`

## Вход в приложение

### Администратор

1. Перейдите на `http://127.0.0.1:8000/admin/`
2. Введите credentials администратора

В админке вы можете:
- Создавать врачей и пациентов
- Управлять новостями (для публикации на главной)
- Просматривать записи на приём и отзывы

### Пациент

1. На главной странице нажмите **"Регистрация пациента"**
2. Заполните форму:
   - **Имя и фамилия**
   - **Телефон** (используется как логин)
   - **Пароль**

После регистрации попадёте в личный кабинет.

### Врач

Врачи создаются только администратором в админке. Для входа врача используются Django User credentials.

## Основные функции

### Главная страница (`/`)

- Герой-секция с описанием клиники
- **Факты о медицине** - рандомные медицинские факты
- **Новости клиники** - управляется администратором в админке
- **Врачи** - выделенные врачи (помечены как "featured" в админке)
- **Форма входа** - для пациентов и врачей

### Личный кабинет пациента (`/patient/dashboard/`)

- Профиль пациента
- История записей на приём
- Возможность оставить отзыв после завершённого приёма
- Просмотр контактной информации врача

### Кабинет врача (`/doctor/dashboard/`)

- Список пациентов
- Таблица всех записей
- Возможность изменить статус записи (ожидание → подтверждено → завершено)
- Кнопка "Назначить пациента" для создания записи

## API & Модели

### Модели данных

- **Patient**: Профиль пациента (телефон, имя, адрес)
- **Doctor**: Профиль врача (специализация, график работы, рейтинг)
- **DoctorBooking**: Запись на приём (пациент, врач, дата/время, статус)
- **Review**: Отзыв о враче (рейтинг, комментарий)
- **News**: Новость для публикации на главной

### URLs основных страниц

- `/` - Главная
- `/admin/` - Админка Django
- `/patient/register/` - Регистрация пациента
- `/patient/login/` - Вход пациента
- `/patient/dashboard/` - Личный кабинет пациента
- `/patient/bookings/` - История записей
- `/patient/logout/` - Выход
- `/doctor/<id>/` - Профиль врача
- `/doctor/dashboard/` - Кабинет врача
- `/doctor/login/` - Вход врача
- `/doctor/logout/` - Выход врача

- Для пациентов используется встроенная Django аутентификация
- Врачи имеют собственные учётные записи (также Django User)
- Защита от CSRF для всех форм
- Логирование входов в админку

## Решение типовых проблем

### Ошибка: "No such table: doctors_doctor"

**Решение**: Примените миграции: `python manage.py migrate`

### Не работает вход

**Проверьте**:
1. Пользователь существует в БД
2. Для пациентов используется телефон (нормализованный без спецсимволов)
3. Убедитесь, что пароль введён правильно (чувствителен к регистру)

### Врач не видит своих записей

**Проверьте**:
1. Врач создан в админке и имеет связанный User
2. Записи созданы для этого врача
3. Вы вошли под той же учётной записью врача
